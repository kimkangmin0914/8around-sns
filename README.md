# around

**한 줄의 글이 대화가 되는 곳.** around는 짧은 글을 올리고, 댓글과 답글로 이야기를 잇고, 곁에 두고 싶은 사람을 팔로우하는 작은 SNS입니다. 이름과 마크는 8around에서 왔습니다 — 가운데를 비운 3×3 격자의 여덟 칸, 그 빈자리가 화면을 보는 당신의 자리입니다.

**[around 사용하기 → frolicking-muffin-3c6498.netlify.app](https://frolicking-muffin-3c6498.netlify.app)** · [GitHub](https://github.com/kimkangmin0914/8around-sns) · [디자인 노트(/brand)](https://frolicking-muffin-3c6498.netlify.app/brand)

## 1. 프로젝트 개요

| 구분   | 기능            | around에서                                                                                                   |
| ------ | --------------- | ------------------------------------------------------------------------------------------------------------ |
| 계정   | 회원가입        | 1단계 이메일·비밀번호 → 2단계 사용자 이름(실시간 중복 확인)·이름·소개. 가운데 빈칸이 내 색으로 채워짐        |
| 계정   | 로그인          | Supabase Auth 쿠키 세션, 보던 대화로 돌아가는 `?next=`, 다른 탭에서 계정이 바뀌면 화면 잠금(SessionBoundary) |
| 소셜   | 팔로우 / 팔로잉 | 프로필·사람들 벽·추천에서 낙관적 팔로우, 「나를 팔로우」 표시와 맞팔로우, 팔로워·팔로잉 탭과 팔로잉 피드     |
| 콘텐츠 | 게시글 작성     | 피드 상단 입력창 + 어디서나 `N` 키로 여는 작성창, `⌘/Ctrl+Enter`, 초안 자동 보관, 500자 링                   |
| 콘텐츠 | 댓글            | 글 상세에서 댓글, 새 댓글 강조, 개수 갱신                                                                    |
| 콘텐츠 | 대댓글          | 댓글 아래 한 단계 답글, 연결선으로 보이는 계층, 답글에 답하면 같은 대화에 `@이름`이 붙음, 긴 대화 접기       |

### 직접 사용해 보기

1. **지금 시작하기**에서 이메일·비밀번호로 가입하고, 사용자 이름과 이름을 정합니다(이메일 인증 없음).
2. 환영 피드에서 첫 글을 올립니다. 오른쪽 「곁에 둘 만한 사람」에서 팔로우하면 **팔로잉** 탭에 그 사람의 글이 모입니다.
3. 다른 브라우저(또는 시크릿 창)에서 두 번째 계정을 만들어 첫 계정의 글에 댓글을 남깁니다.
4. 첫 계정으로 돌아와 그 댓글에 **답글**을 달고, 답글에 다시 답해 봅니다 — 같은 대화 안에 `@이름`과 함께 이어집니다.
5. 프로필의 **팔로워 / 팔로잉** 숫자를 눌러 같은 관계가 양쪽에 보이는지 확인합니다. 팔로잉 버튼에 마우스를 올리면 언팔로우로 바뀝니다.

> 과제용 서비스입니다. 메일로 비밀번호를 찾을 수 없으니 다른 곳에서 쓰는 비밀번호는 피해 주세요. 글·댓글은 수정·삭제할 수 없습니다.

## 2. 로컬 실행 방법

준비물: **Node.js 24**, **Docker**(로컬 DB용; macOS는 Docker Desktop이나 `brew install colima docker && colima start`).

```bash
git clone https://github.com/kimkangmin0914/8around-sns.git
cd 8around-sns
npm ci

npm run db:start   # 로컬 Supabase(Postgres·Auth·REST) 실행 + 마이그레이션 + 예시 데이터
npm run db:env     # 로컬 주소와 publishable key로 .env.local 작성 (secret 키는 쓰지 않음)
npm run dev        # http://127.0.0.1:3000
```

로컬 예시 데이터에는 여덟 명(`harin@around.test` 등, [`supabase/seed.sql`](supabase/seed.sql))과 글·댓글·답글·팔로우가 들어 있습니다. 예시 계정 비밀번호는 seed 파일 맨 위에 적혀 있습니다. 처음 상태로 되돌리려면 `npm run db:reset`, 끄려면 `npm run db:stop`.

본인의 Supabase 프로젝트에 붙이려면 [`supabase/migrations`](supabase/migrations)를 SQL Editor에서 한 번 실행하고, `.env.example`을 `.env.local`로 복사해 **Project URL**과 **publishable key**(`sb_publishable_…`)를 넣습니다. Auth 설정에서 Email 가입은 켜고 Confirm email·익명 로그인은 끕니다.

## 3. 기술 스택 선택 이유

- **Next.js 16 (App Router) + React 19 + TypeScript** — 서버 컴포넌트로 첫 화면을 데이터와 함께 그리고, 쓰기는 Server Action으로 같은 저장소 안에서 끝냅니다. 클라이언트로 내려가는 것은 상호작용이 있는 섬(입력창, 팔로우 버튼, 대화 목록)뿐입니다.
- **Supabase (Auth + Postgres + RLS)** — 인증을 직접 만들지 않고, 권한은 DB가 최종 판단하게 했습니다. 화면을 거치지 않은 요청도 작성자 사칭·답글의 답글·자기 팔로우가 막힙니다. Supabase CLI로 같은 스택을 로컬 Docker에 띄워 RLS까지 검사합니다.
- **CSS Modules + 디자인 토큰** — 격자선, 색 짝, 한쪽만 날카로운 모서리 같은 규칙을 토큰으로 정의하고 컴포넌트별 모듈에서만 씁니다. 유틸리티 프레임워크와 UI 키트는 걷어냈습니다. 아이콘 36종과 마크는 SVG로 직접 그렸습니다.
- **Pretendard + Archivo Expanded** — 한글은 Pretendard 동적 서브셋(필요한 글자 조각만 로드), 숫자와 `@이름`은 넓은 그로테스크로 Dropbox의 Sharp Grotesk 같은 인상을 냅니다. 둘 다 OFL이며 자체 호스팅합니다.
- **Netlify** — 기존 배포 경로를 그대로 씁니다. `main`에 push하면 빌드·배포됩니다.

## 4. 하네스 구성

"새 사람이 와도 같은 품질로 기능을 더할 수 있는가"에 답하기 위한 장치들입니다.

| 장치                                                          | 무엇을 막는가                                                                                        |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [`AGENTS.md`](AGENTS.md) · `CLAUDE.md`                        | 사람·AI 에이전트가 같은 규칙으로 작업: 폴더 역할, 쓰기는 `requireAuthor`, 스키마는 새 마이그레이션만 |
| [`DESIGN.md`](DESIGN.md) + `src/styles/tokens.css` + `/brand` | 화면마다 다른 색·간격·움직임. 문서·토큰·살아 있는 견본이 같은 값을 가짐                              |
| `npm run check`                                               | Prettier → ESLint(react-hooks 규칙 포함) → `tsc` → 단위 검사 71개                                    |
| `npm run test:db`                                             | 로컬 Supabase에 진짜 계정 둘을 만들어 RLS·컬럼 권한·답글 깊이 트리거·팔로우 제약 13가지를 검사       |
| `supabase/` (config · migrations · seed)                      | 누구나 같은 DB를 1분 안에 재현. seed가 화면 검토용 대화를 채움                                       |
| GitHub Actions 2개 작업                                       | `check`+`build`, 그리고 Docker로 Supabase를 띄운 `test:db`. PR과 `main`마다                          |
| Netlify                                                       | 빌드만 담당(`netlify.toml`). 지난 배포가 실패한 원인(빌드 캐시 `.netlify/`를 ESLint가 검사)을 해결   |

단위 검사는 검증 규칙, 본문 토큰(@멘션·링크), 색 배정, 상대 시간, 목록 병합, 그리고 Server Action의 경계(비로그인·익명·다른 계정·사칭 필드·답글의 답글·다른 글의 댓글·자기 팔로우·저장 결과 재확인)를 모의 클라이언트로 확인합니다. **모의 검사는 DB를 대신하지 않으므로** 같은 규칙을 `test:db`가 실제 Postgres에서 다시 확인합니다.

## 5. 구현 중 내린 결정과 트레이드오프

**디자인: Dropbox Brand의 언어를 SNS의 문법으로.** 보이는 파란 격자 위에 글을 행으로 놓고(카드 대신 격자선), 사람마다 여덟 색 짝 중 하나를 줘서 이름보다 색으로 먼저 알아보게 했습니다. 메뉴는 Dropbox처럼 타일이 사방에서 모여 벤토가 되고, 랜딩 문장은 스크롤에 따라 외곽선에서 채워집니다. 장식은 설명이 되는 것만 남겼습니다 — 소개 벤토의 네 타일은 그대로 네 가지 기능의 설명입니다.

**정보 구조: BandLab의 3단.** 탐색(레일) → 콘텐츠(피드·대화) → 발견(내 카드·추천)으로 나눴고, 프로필은 신원 → 숫자 탭 → 목록 순서입니다. 휴대폰에서는 상단 바와 하단 탭(가운데 큰 +)으로 접힙니다.

**운영 스키마는 그대로.** 색은 사용자 id 해시로 정해 DB에 저장하지 않고, 쿼리는 기존 FK·카운트 임베드만 씁니다. 덕분에 배포 시 운영 DB 마이그레이션이 필요 없습니다. 대신 사람이 색을 고를 수는 없습니다.

**답글은 한 단계 + @멘션.** DB 트리거가 답글의 답글을 막는 기존 규칙을 유지했습니다. 답글에 답하면 같은 최상위 댓글 아래에 붙고 상대의 `@이름`을 자동으로 넣어 "누가 누구에게"를 보존합니다. 무한 들여쓰기 대신 휴대폰에서도 읽히는 깊이를 택했습니다. 답글이 3개를 넘으면 2개만 보이고 나머지는 펼칩니다.

**서버가 확인한 뒤에만 성공.** 글·댓글은 저장 응답을 받은 뒤 입력창을 비우고, 응답이 끊기면 "불확실" 상태로 초안을 남깁니다. 팔로우만 낙관적으로 먼저 바꾸고, 저장 후 관계를 다시 읽어 다르면 되돌립니다. 추천 목록은 방문 동안 고정해 팔로우한 사람이 손 밑에서 사라지지 않게 했습니다.

**키셋 페이지네이션.** `(created_at, id)` 커서로 "더 보기"를 이어 붙여 새 글이 들어와도 중복·누락이 없고, 새로고침된 첫 페이지와 이어 붙인 페이지를 합칠 때 밀려난 글을 보존합니다. 읽기용 Server Action을 쓴 것은 단순함을 위한 선택으로, 요청이 직렬화되는 비용이 있습니다.

**하지 않은 것.** 좋아요, 이미지, 알림, 글 수정·삭제, 프로필 수정, 메일 인증·비밀번호 찾기는 과제 범위 밖이라 버튼도 만들지 않았습니다.

## 6. 시간이 더 있었다면

- **사람이 고르는 색과 프로필 편집** — 가입 마지막 단계에서 여덟 색 중 하나를 고르게 하고(`profiles.tone` 마이그레이션), 이름·소개를 고칠 수 있게.
- **실시간과 알림** — 내 글에 댓글·답글이 달리면 Supabase Realtime으로 대화에 바로 나타나고, 레일에 알림 점이 켜지게.
- **E2E 검사** — 지금은 브라우저 확인을 사람이(Claude in Chrome으로) 했습니다. Playwright로 가입→글→댓글→답글→팔로우를 CI에서 로컬 Supabase에 대고 돌리고 싶습니다.
- **중복 없는 재시도** — 클라이언트가 만든 멱등 키로 같은 글이 두 번 저장되지 않게.
